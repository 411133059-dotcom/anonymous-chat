# 匿名聊天室 設計結果

> 這份文件記錄 /design 的成果，給下一步用 /frontend-design 做前端時使用。
> 畫面「有哪些元素、做什麼事」的規定在 `docs/architecture.md` 第 7 節；這裡記的是「長什麼樣子」。

## 設計稿位置

設計畫布（私人連結，只有建立者能開，要給別人看需從頁面的 Share 選單分享）：
https://claude.ai/artifact/MaxB8kAUvcJBXbBceR4Xwi

畫布裡共 11 個畫面，下面「畫面對照」一節列出每個畫面的名稱與用途。
所有畫面都是靜態稿，沒有互動；圖片位置都是標示「圖片」的灰色佔位框，不是真的照片。

## 風格方向

「深夜聊天室」：深墨色底，只有一個萊姆黃綠色的重點色。
重點色只用在兩處：**自己的訊息**與**送出鈕／進入鈕**。這樣一眼就能分辨哪些是自己說的，也不會讓畫面花掉。
手機優先；電腦版是把同樣的內容置中成一欄。

## 設計 token

對比：主要文字與次要文字在深底上都達到可讀標準；自己的氣泡是深色字配重點色，對比最高。

### 字型

| 用途 | 字型 |
|---|---|
| 中文與一般文字 | Noto Sans TC（400、500、700、900） |
| 時間、數字（時間戳、倒數） | DM Mono（400、500） |

兩者都從 Google Fonts 載入。

### 尺寸與形狀

- 手機畫面：390×844；電腦畫面：1280×800，聊天欄寬 760。
- 所有可按的東西至少 44px 高。
- 輸入框文字 16px 以上（避免 iPhone 自動放大）。
- 訊息文字 15px，代號 12px，時間 11px，系統灰字 12px。
- 氣泡圓角：別人的左上角小（4px）、其餘 18px；自己的右下角小（4px）、其餘 18px。
- 按鈕與輸入框多為膠囊形（圓角約等於高度的一半）。
- 圖示一律是線條圖示，不使用 emoji 當圖示。

## 版面結構（聊天室）

由上到下四塊，整個畫面不捲動，只有訊息區自己捲動：

1. **上方列**（高 60，電腦版 68）：左邊房名「匿名聊天室」，右邊「N 人在線」按鈕與「離開」按鈕。
2. **連線狀態條**（只在斷線時出現，位於上方列正下方）。
3. **訊息區**：撐滿剩下的空間，內容靠底部排列。
4. **輸入區**：選圖片鈕、貼網址鈕、文字框、送出鈕。

### 訊息的呈現

| 種類 | 樣子 |
|---|---|
| 別人的文字 | 靠左；氣泡上方一行次要色的代號；氣泡右邊一個小的時間 |
| 自己的文字 | 靠右；沒有代號；時間在氣泡左邊；重點色氣泡 |
| 圖片 | 與文字相同的左右規則；手機 220×132、電腦 300×180 的縮圖，可點擊放大 |
| 圖片載入失敗 | 虛線框＋叉號圖示＋「圖片無法載入」 |
| 系統提示 | 置中的次要色小字，沒有氣泡（例如「夜貓 進入了聊天室」） |
| 最早的訊息 | 置中小字「已經是最早的訊息」 |
| 載入更早訊息 | 置中的轉圈圖示＋「載入更早的訊息…」 |

別人的訊息旁有紅色的「檢舉」小按鈕（旗子圖示）。設計稿裡是直接顯示出來；
按 architecture.md 的規定，實作時手機是**長按**後才出現、電腦是**滑過**後才出現。
按鈕的點擊範圍要保持 44px 高，視覺上可以比較小。

### 輸入區

- 預設：文字框顯示灰色提示「輸入訊息…」；送出鈕為重點色。
- 空白時：送出鈕變灰並停用。
- 斷線時：四個元件全部停用，文字框提示「連線中，暫時無法送出…」。
- 電腦版提示改為「輸入訊息，按 Enter 送出，Shift + Enter 換行」。
- 被擋下時（例如送太快）：輸入區上方出現一條紅色底的提示「請稍後再送」，輸入框內容保留。

### 重點畫面說明

**輸入代號**
- 標題「匿名聊天室」＋一行說明「不用註冊，不用登入。取一個代號，就能和大家聊天。」
- 輸入框標籤「你的代號」，下方永遠顯示格式提示「1–12 個中文、英文或數字」。
- 錯誤時：輸入框邊框變紅，下方出現紅字與圖示；使用者開始修改時錯誤消失。
- 畫面最底下一行小字：「展示版：目前看到的是模擬資料，不同裝置之間不會互通」（階段二接上 Supabase 後移除）。

**被踢出**
- 與輸入代號畫面同一個版型，標題換成「你已被踢出聊天室」，說明「有 3 位不同的使用者檢舉了你。」
- 中間一塊倒數區：「約 ○○ 分鐘後可再進入」，數字用等寬字型。
- 輸入框與進入鈕停用，按鈕文字為「進入（暫時無法使用）」。

**在線名單**
- 點上方列的人數鈕展開；展開時人數鈕邊框變重點色、箭頭向上。
- 浮在訊息區上方，距離左右各 12px；底下的訊息與輸入區壓暗，表示目前焦點在名單。
- 每一列：小圓點、代號、右邊「檢舉」。自己那一列沒有檢舉，改為重點色的「我」標籤。

**確認對話框**
- 標題＋一段說明＋兩顆按鈕（取消為外框、確認為實心）。
- 離開的確認鈕是重點色；檢舉的確認鈕是危險色。
- 檢舉的說明文字要寫清楚規則：3 位不同的人檢舉會被踢出，1 小時內不能再用同一個代號。

**選圖預覽**
- 選好檔案後先出預覽，並說明「原本 6.4 MB，已自動壓縮為 1.3 MB」（數字是範例）。
- 沒壓縮時不顯示這一行。

## 給前端實作的注意事項

- 設計稿裡的文字、顏色、尺寸是依據，不是要逐字複製；名單人名、時間、數字都是範例資料。
- 設計稿的 HTML 為了在畫布上顯示，每個畫面都是獨立檔案、樣式全寫在標籤上。實作時請把上面的 token 抽成共用的 CSS 變數，各畫面共用同一套元件（上方列、氣泡、輸入區、對話框），不要照抄重複的寫法。
- 設計稿的「輸入代號」與「被踢出」兩個畫面，表單上有一段直接寫在標籤上的送出攔截語法，只是為了讓稿面不要真的送出，實作時不要沿用，改用框架本身的事件處理。
- 圖示請沿用同一組線條圖示（粗細約 1.6–2.4）；設計稿用到的有：圖片、連結、送出、向下／向上箭頭、旗子（檢舉）、叉號、轉圈、禁止、對話泡泡。
- 斷線提示條與轉圈圖示在設計稿中是靜態的，實作時轉圈要有旋轉動畫，並遵守使用者的「減少動態效果」系統設定。
- 亮色版沒有設計。architecture.md 沒要求，如果之後要做，需要另外設計一組對應的色票。
- 手機的實際高度要用 `100dvh`，輸入區要避開鍵盤與手機底部手勢條（設計稿用底部 24px 留白代表）。
